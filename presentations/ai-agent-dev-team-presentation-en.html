13 / 44Skill Best Practise
Turn quality into visible feedback

The real quality comes fromTesting, validation and continuation.

  • Complex task-writing workflow.Clear, continuous steps and checklist to reduce the probability of missing steps.

33 / 44RAG: Distillation Layer
RAG quality is decided before retrieval

Fix the unit of knowledge
before tuning the vector stack.

A distillation layer turns documents into smaller, cleaner, governed question-answer units before vectorization.
  • The chunk is the hidden assumption. Token-based chunks have no idea boundary, version context, or access state, so retrieval can return incomplete or conflicting evidence.
  • Use a question-answer packet. One validated claim plus typed governance fields makes the indexed unit match the way users actually ask questions.
  • Distill before vectorization. In the supplied benchmark, semantic deduplication cut the corpus by up to 40x, reduced query tokens by 3x, and improved retrieval distance by about 2.3x.
  • Make governance part of the data. Version state, clearance, privacy, and source metadata travel with each block instead of living as fragile orchestrator logic.
  • Seven stages make failures localizable. Scope, ingest, extract, deduplicate, auto-tag, validate with SMEs, then export to the vector store.
The practical rule: clean and structure the knowledge unit upstream; keep retrieval, reranking, and embeddings focused on matching it.

35 / 44Agentic Design Patterns / Decision Tree
Pattern selection starts with the task

Pick the pattern from task properties.
Do not start with the architecture.

Decision-tree approach to choosing an agentic design pattern.
  • 1. Start with the path. If the solution is known and deterministic, use a sequential workflow; use the model only where interpretation or generation is needed.
  • 2. Add capability as needed. For open-ended work, tools and external information provide access to APIs, databases, documents, and system actions.
  • 3. Separate planning from exploration. Use Planning when stages and dependencies are clear; use ReAct when structure emerges through execution.
  • 4. Spend for quality deliberately. Add Reflection when quality criteria are explicit and the cost of errors justifies extra latency.
  • 5. Scale only for a real bottleneck. Use Multi-Agent for specialization or scale; otherwise, a single agent is usually enough.
Patterns are starting points. Re-evaluate them as feedback, constraints, and failure signals accumulate.Source article
36 / 44Agentic Design Patterns / Framework
A pattern is a composition of capability and execution shape

Use two lenses to place the pattern:
what the agent does and how work moves.

Agent Design Pattern Framework: cognitive function x execution topology.
  • Cognitive function is the vertical lens. Perception, memory, reasoning, action, reflection, collaboration, and governance describe the work being performed.
  • Execution topology is the horizontal lens. Chain, route, parallel, loop, hierarchy, and orchestration describe how work and control flow.
  • Patterns are composable primitives. Examples include RAG Pipeline, Tool Dispatch, Plan-and-Execute, Fan-Out / Gather, and Hierarchical Delegation.
  • Cross-cutting planes keep the system operable. Observability, Evaluation & Validation, and Security & Identity apply across the matrix.
  • Design implication: locate the needed capability and topology first, then combine the smallest set of patterns that solves the task.
The tree chooses; the matrix composes.
