Harness 把一次模型调用，

Agent = LLM + Harness

LLM 负责思考，Harness 负责执行。

while not finished: prompt → LLM if tool requested: execute tool append result else: return answer
RUNTIME / WHEREAgent class、State、Session、Routing、WebSockets、Scheduling 和 Observability，让 Agent 有地方运行并保持持久。

怎么选：需要控制模型调用、消息格式和工具循环，就自己搭；想快速获得记忆、Workspace tools、Streaming 和 Durable recovery，就用现成 Harness。

05 / 20HARNESS
Harness 是 Agent 的操作系统

在正确的时间，
把正确的上下文交给模型。

组织上下文固定指令、动态信息、记忆和检索结果。
执行行动解析模型输出，调用工具并接收外部结果。
管理状态重试、摘要、压缩、权限、预算与人工审批。
判断终点验证结果，决定继续循环还是停止任务。

主任务：把固定上下文与动态上下文组织成模型此刻真正需要的信息，并把模型的输出变成下一步可执行的行动。

  • 任务接近模型已经学过的工作方式
  • 需要快速验证价值
  • 还没有足够的真实任务数据

自建 / 深度定制

  • 任务明显偏离模型训练分布

10 / 20LONG CONTEXT
Context Rot

上下文越长，
不一定越聪明。

性能随输入增长而退化即使任务很简单，模型也不会均匀处理第 100 个和第 10,000 个 token。
干扰项会放大退化相似但无关的信息、长历史和复杂结构都会增加检索难度。
存在上下文，不等于能用真正重要的是信息如何被筛选、压缩和呈现给模型。

长上下文评测不能只测“窗口能装多少”。Source: Chroma Context Rot

11 / 20CONTEXT MANAGEMENT
Context management

不要把所有结果
都留在上下文里。

01 / TOOL OUTPUT大结果产生搜索、日志、代码和 API 返回可能远超当前任务所需。
→
02 / OFFLOAD写入文件把原始结果放进可回溯的文件或外部存储。
→
03 / SUBAGENT提炼结论 / Todo让 Sub-agent 处理细节，只产出决策需要的摘要。
→
04 / MAIN AGENT保留小上下文主 Agent 读取结论、Todo 和文件索引，继续做判断。
触发压缩：接近 Token 预算或上下文增长过快。
保留细节：原始结果仍可通过文件路径回溯。
输出边界：Sub-agent 交付结论和 Todo，不交付过程噪音。
主 Agent 保留判断，文件承载细节，Sub-agent 负责提炼。
12 / 20DEBUGGING
Agent 效果排查

不要先改 Prompt。
先保存完整失败轨迹。

01
抓取完整上下文用户输入、模型输出、工具参数、API 返回、记忆和状态。
02
在错误处设断点找到第一次偏离目标的位置，而不是只看最后的错误答案。
03
重放同一任务固定输入和环境，保留现场，减少非确定性带来的干扰。
04
做针对性消融一次只改变一个变量，确认到底是哪一环影响了结果。
# one failed run, one replayable trace trace = { "input": user_message, "model_calls": calls, "tool_args": tool_args, "api_returns": observations, "memory": retrieved_context, "score": final_reward }
13 / 20ABLATION
一次只改变一个变量

用消融实验，
把模糊问题变成可验证假设。

工具结果消融删除冗余字段，观察模型是否更容易抓住关键事实。
记忆深度消融压缩历史记忆，测试是否存在上下文过长和注意力稀释。
工具定义单测用纯净指令单测工具 schema，排除上下文噪声的影响。

可继续对照：移除一个 Skill、固定模型只换上下文、固定上下文只换 Harness 流程、比较修复前后的成功率和轨迹长度。

如果不知道哪一环出了问题，就无法精准优化。

19 / 20MEMORY / SKILL / WEIGHT
Agent 的三种学习方式

Memory 记住经历，
Skill 复用流程，
Weight 长出能力。

01 / NOTEBOOK

Memory

把发生过什么记录下来，下次检索后塞进上下文。

  • 简单、灵活、适合个性化
  • 检索不到就等于不存在
  • 记住事实，不一定形成能力
02 / PLAYBOOK

Skill

把跑通的流程压缩成可复用的操作手册。

  • 比单次记忆更稳定
  • 适合规则明确的经验
  • 仍然占用上下文，仍需模型执行
03 / CAPABILITY

Weight

把经验直接训练进模型权重，让判断力和手感长期存在。

  • 不需要每次检索
  • 不依赖额外上下文
  • 面对新问题可以直接发挥

22 / 28DEEPSEEK / DURABLE TRACE
从运行时到可恢复状态

一轮请求，
落成可恢复的事件轨迹。

01turn/start领取输入，开启一轮工作。
02pre-step决定这一轮模型看见什么。
03llm/stream保存模型输出和流式片段。
04tool/call经过校验、执行和结果管道。
05step/end结束一次模型请求加工具调用。
06next step仍有工具或新输入就继续。
07turn/end没有欠账后才关闭这轮。
Model-visible = logged任何进入模型请求的内容，都必须能从 Session Log 重建；这让 resume、fork、replay 和 Telemetry 共用一条事实源。
Durable facts ≠ live hooksSession events 负责持久化事实；Agent、Tool 和 Capability events 负责拦截或观察运行中的动作。
可调试的关键不是更多日志，而是可重放的因果链。Source: DeepSeek Harness Turn Flow

27 / 28PI / RUNTIME CONTROL
控制不是一个开关，而是一组运行时动作

真正的可控性，
来自运行中的选择。

Steer当前工具链结束后立刻插入新指令，改变方向。
Follow-up等当前工作自然完成，再追加下一项任务。
Compaction把长历史压缩成 goal、progress、decisions 和 next steps。
Tree navigation在同一个 session 文件里回到旧分支，必要时生成 branch summary。

设计含义：用户不必等 Agent “做完再纠正”；Harness 把中断、排队、恢复、分支和压缩都变成显式操作。

把长任务的复杂度放进运行时状态，而不是让模型自己记住所有控制规则。Source: Pi Compaction and Branch Summarization
