# Release notes procedure

1. Identify the user-visible change, affected audience, and any limitation.
2. Lead with the outcome instead of the implementation detail.
3. Use one short heading and three or fewer bullets.
4. Mention migration or compatibility concerns when they are explicitly known.
5. Never invent performance numbers, availability, or supported platforms.

Return Markdown suitable for a changelog. Keep the language concrete and avoid
internal ticket IDs.
